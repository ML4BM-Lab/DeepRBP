
# Real knockdowns: validation of DeepRBP explainability using real RBP knockdown RNA-seq data
This submodule validates **DeepRBP explainability scores** using real RNA-binding protein (RBP) knockdown RNA-seq experiments.
It tests whether genes and transcripts that respond transcriptionally to an RBP knockdown receive **higher explainability scores** from DeepRBP under control conditions.

This analysis constitutes a functional validation of DeepRBP predictions, complementary to:

- **POSTAR3 binding validation**, and
- **complex-level analyses (CORUM)**.

---

## Conceptual overview
The validation strategy follows five main steps:

1. **RNA-seq quantification** of control and knockdown samples (Kallisto)
2. **Differential expression (DE)** analysis (voom-limma)
3. **Preprocessing of real KD data** into DeepRBP-compatible inputs
4. **Model evaluation and explainability** on control data
5. **Comparison of explainability scores** between DE and non-DE genes/transcripts

The central hypothesis is:
> Genes or transcripts that are differentially expressed upon RBP knockdown should show higher **DeepRBP explainability scores** for that RBP under control conditions.

## Step 1 — RNA-seq quantification (Kallisto)
Raw RNA-seq FASTQ files are quantified at the transcript level using **Kallisto**.

### Environment
```bash
conda create -n kallisto_env -c bioconda kallisto
conda activate kallisto_env
```

### Dataset-specific SLURM scripts
Each dataset has a dedicated SLURM script that:

1. Downloads FASTQs from GEO / ENA
2. Builds a Kallisto index (GENCODE v23, once)
3. Runs Kallisto with bootstrapping
4. Writes per-sample outputs

Example (GSE136366):
```bash
sbatch slurm/explainability_module/real_knockdowns/kallisto_quant/download_GSE136366_kd_data.sh
```

Go to `slurm/explainability_module/real_knockdowns/kallisto_quant` to see how to download the rest of datasets.
### Expected output structure
```text
<data_root>/GSE136366/
  kallisto_output/
    SRRxxxx/
      abundance.tsv
      abundance.h5
  info_samples.txt
```

### The `info_samples.txt` file
Each dataset folder **must contain** an `info_samples.txt` file, which is **provided in this repository** and does **not** need to be generated by the user.

This file defines the experimental design by mapping each RNA-seq sample to its biological condition (control or knockdown). It is required by downstream steps (differential expression, preprocessing, and explainability).

The file is a **tab-separated text file** with the following columns:

- **`run_accession`**: Sample identifier (must match the Kallisto output folder name, e.g. `SRR10045016`)
- **`sample_title`**: Condition label used to distinguish control vs knockdown samples

Example (`GSE136366/info_samples.txt`):
```text
run_accession   sample_title
SRR10045016     tdp43_ko
SRR10045017     tdp43_ko
SRR10045018     tdp43_ko
SRR10045019     Rescued_tdp43
SRR10045020     Rescued_tdp43
SRR10045021     Rescued_tdp43
```

**Important notes:**
The values in `sample_title` must be used consistently in later steps
(e.g. `--condition_control` and `--condition_knockdown`).

The script assumes that each `run_accession` has a corresponding folder
inside `kallisto_output/`.

Do **not rename** this file or change column names unless you also update the scripts.

## Step 2 — Differential expression (voom-limma)
Differential expression (DE) analysis is performed **outside the DeepRBP model**, using transcript-level abundance estimates obtained with **Kallisto**.
This step is used to validate explainability results against real knockdown (KD) RNA-seq experiments.

Specifically, differential expression is computed with the **voom–limma** framework, applied to **FPKM values estimated from Kallisto pseudo-counts**, and is executed in batch via a single SLURM-friendly 
shell script (`run_voom-limma_kd.R`).

### What this step does
For each real knockdown dataset:

1. Loads transcript-level expression matrices derived from Kallisto
2. Computes transcript-level FPKM values from Kallisto estimated counts
3. Performs voom normalization and linear modeling with limma
4. Identifies differentially expressed transcripts
5. Summarizes DE at the gene level by selecting, for each gene, the transcript with the lowest adjusted p-value
6. Generates volcano plots for transcript-level DE

### Significance criteria (as used in the paper)
By default, transcripts / genes are considered differentially expressed if:

- |log2(Fold Change)| > 1
- Nominal P-value < 0.01

(Thresholds are configurable in the batch script.)

### How to run (recommended)
#### Run all limma analyses in batch
All datasets are processed through a single entry point:
```bash
sh run_limma_batch.sh
```

This script:
- loops over all configured knockdown datasets
- runs transcript-level DE with voom–limma
- produces gene-level summaries
- generates volcano plots
- organizes outputs in a structured results folder

No direct invocation of `run_voom-limma_kd.R` is required.

### Script locations
- **Batch launcher (recommended entry point)**
```bash
slurm/explainability_module/real_knockdowns/de_limma/run_limma_batch.sh
```

- **Core DE implementation (called internally)**
```bash
src/deeprbp/explainability_module/de_limma/run_voom-limma_kd.R
```

- **Shared statistical core**
```bash
src/deeprbp/explainability_module/de_limma/voom_limma_core.R
```

### Output structure
For each dataset, results are written to:

```text
output/results/real_knockdowns/de_limma/
  logFC1_pvalue0.01/
    <DATASET>/
      voom_limma_output/
        DE_transcripts_<KD>_vs_<CTRL>.csv
        DE_genes_<KD>_vs_<CTRL>.csv
        volcano_Transcripts_DE_KD_vs_Control.{png,pdf}
```

### Notes
- DE is performed at the transcript level first
- Gene-level DE is a summary step, not an independent analysis
- This step is typically run once per dataset, before any DeepRBP-specific analysis


## Step 3 — Preprocess real KD data for DeepRBP
This step converts **Kallisto transcript-level TPMs** into **DeepRBP-compatible** input matrices, following **exactly the same preprocessing** and **feature construction pipeline used during model training**.

It is applied to real knockdown **RNA-seq datasets** and generates separate inputs for control and knockdown conditions.

### Script
```swift
src/deeprbp/explainability_module/real_knockdowns/preprocess_data/preprocess_realkd_data.py
```

This script is typically exposed via the CLI entry point:
```kotlin
preprocess-realkd-data
```

### What this step does
For each experimental condition (control / knockdown), the script:

1. **Loads Kallisto TPMs**
  - Transcript-level and gene-level TPMs are read from `kallisto_output/`

2. **Cleans expression data**
  - Ensures consistent identifiers
  - Handles missing values and formatting

3. **Builds DeepRBP model inputs**
  - Uses the provided feature specification to select and order:
    - RBPs
    - genes
    - transcripts
  - Follows the same input construction logic as in training

4. **Applies expression transformations**
  - TPMs are transformed using the same scheme as training
  (`log2(x + 1)` internally)

5. **Splits data by experimental condition**
  - Control and knockdown samples are processed independently

6. **Writes DeepRBP-ready matrices to disk**

### ⚠️ Important: how conditions are defined
The script does not infer conditions automatically.

The values passed to `--condition_control` and `--condition_knockdown` **must exactly match** the labels used in the `info_samples.txt` file.

Before running this step, always inspect:
```bash
<DATASET>/info_samples.txt
```

and identify the correct values in the column that encodes experimental conditions
(e.g. `sample_title`).


### Example usage
Activate the DeepRBP environment:

conda activate DeepRBP

#### Example 1 — PRJEB39343 (MBNL1 knockdown)
```bash
preprocess-realkd-data \
  --path_dataset "/scratch/.../PRJEB39343" \
  --output_dir "/scratch/.../PRJEB39343/processed" \
  --feature_spec "/scratch/.../DeepRBP_feature_spec.xlsx" \
  --condition_control "HFE145siNeg_1" \
  --condition_knockdown "HFE145siMBNL1"
```

#### Example 2 — GSE75491 (RBM47 knockdown)
```bash

  --output_dir "/scratch/jsanchoz/DeepRBP/data/explainability_module/real_kds/GSE75491/processed" \
  --feature_spec "/scratch/jsanchoz/DeepRBP/data/training_module/DeepRBP_feature_spec.xlsx" \
  --condition_control "Control" \

```

#### Example 3 — GSE136366 (TDP-43 knockout)

For each dataset, the following structure is created:
```text

  knockdown/
```

Each subfolder contains **DeepRBP-ready input matrices** for one experimental condition.


## Step 4 — Model evaluation and explainability on real knockdown data (POR AQUI !!!!)
In this step, a **pretrained DeepRBP model** is applied to real knockdown (KD) RNA-seq data to:

1. Evaluate model predictions on both *control* and *knockdown* samples
2. **Compute explainability scores exclusively on control samples**

Explainability is restricted to the control condition to avoid confounding attribution signals caused by **experimental perturbations**.

CLI
```text
run-deeprbp-realkd
```

This command wraps:
```swift
src/deeprbp/explainability_module/real_knockdowns/main_real_knockdowns.py
```

### Inputs
**Required**
- Processed real KD data (from Step 3), containing:
```text
processed/
  control/
  knockdown/
```

- **Trained DeepRBP model checkpoint**
- **YAML configuration file** defining model, explainability and aggregation parameters

### Configuration (YAML)
The pipeline is driven by a YAML configuration file, structurally similar to the one used for TCGA explainability.

Typical fields include:

```yaml
scaler_dir: ".../scaler"
model_checkpoint_path: ".../model.ckpt"

explanation_method: "DeepLIFT"
reference_data: "knockout_reference"

batch_reduction_method: "t-statistic"
gene_collapse_method: "max_absolute_value"

getBM_path: ".../getBM.csv"
```

Notes:
- `reference_data` defines the baseline used by the explainability method
- `batch_reduction_method` controls how per-sample attributions are aggregated
- `gene_collapse_method` controls transcript → gene aggregation

### Command-line arguments
```text
--config_path            YAML configuration file (default provided)
--processed_data_dir     Path to processed real KD data (Step 3 output)
--output_dir             Output directory for evaluation and explainability results

--evaluate_predictions   Whether to run prediction evaluation (True / False)
--scaler_mode            Scaler strategy:
                          • tcga    → use pretrained TCGA scaler (default)
                          • fit_new → fit a new scaler on real KD data
```

### Example
```bash
run-deeprbp-realkd \
  --config_path config_real_knockdowns.yaml \
  --processed_data_dir "/scratch/.../PRJEB39343/processed" \
  --output_dir "/scratch/.../real_knockdowns/PRJEB39343"
```

### What the script does
- Loads processed control & knockdown data
- Evaluates model predictions on both
- Computes explainability on control samples only
- Writes standard explainability outputs:
  - df_scores_TxRBP.csv
  - df_scores_GxRBP.csv
  - result_table.csv

### Notes and best practices
- Explainability is intentionally restricted to control samples
- Knockdown samples are used only for prediction evaluation
- Use scaler_mode=tcga unless you explicitly want to recalibrate the feature space

### Running in batch (HPC / SLURM) (recommended for multiple datasets)
When analyzing multiple real knockdown datasets, Step 4 is typically executed in batch on an HPC cluster using SLURM job scripts.
These scripts wrap the run-deeprbp-realkd CLI and ensure reproducible execution across datasets, logging, and resource control.

Two common execution patterns are provided:

#### Single-dataset SLURM job
For running explainability on a single real knockdown experiment:
```bash
sbatch run_realkd_single_dataset.sh
```

Internally, this script activates the DeepRBP environment and calls:
```bash
python -m deeprbp.explainability_module.real_knockdowns.main_real_knockdowns \
  --config_path config_real_knockdowns.yaml \
  --processed_data_dir <DATASET>/processed \
  --output_dir <RESULTS>/<DATASET>
```

#### Multi-dataset batch SLURM job

For running Step 4 across multiple real knockdown datasets in a single submission:
```bash
sbatch run_realkd_all_datasets.sh
```

This batch script:

- iterates over all the example datasets in this tutorial
- produces one output folder per dataset
- captures logs per execution
- Both scripts are located under: `slurm/explainability_module/real_knockdowns/`

## Step 5 — Compare explainability scores between DE and non-DE entities
This final step tests whether differentially expressed (DE) genes or transcripts exhibit higher DeepRBP explainability scores than non-DE ones.

### Script
This analysis is performed using:
```bash
real_knockdowns/plot_results/generate_realkd_plot.R
```

and is typically executed via:
```bash
sh slurm/explainability_module/real_knockdowns/run_post_scores_analysis.sh  
```

### Analysis overview
For each experiment and its corresponding knocked-down RBP:

1. Load differential expression (DE) results from voom-limma
2. Label transcripts / genes as DE or non-DE
3. Load DeepRBP explainability scores (control samples only)
4. Extract absolute explainability scores for the RBP of interest
5. Compare DE vs non-DE entities using statistical testing
6. Generate publication-ready boxplots

### Output
transcripts_arranged.pdf
genes_arranged.pdf

Each figure aggregates multiple experiments, with statistical annotations.

### Statistical tests (paper consistency)
- DE calling: voom-limma (Law et al., 2014)
- Score comparison: one-sided Mann–Whitney–Wilcoxon
- Hypothesis:
  - DE entities have higher explainability scores than non-DE entities

### Notes and common pitfalls
- Explainability is computed on control samples only
- DE analysis uses estimated counts, not TPMs
- Transcript versions are stripped (ENST…​.X → ENST…)
- Gene-level DE is summarized conservatively
- All score comparisons use absolute values
